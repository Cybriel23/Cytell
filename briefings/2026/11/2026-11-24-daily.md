## 1. Risk Watch

### 1.1 ConnectWise ScreenConnect CVE-2026-84869 exploited against MSP technician workstations (ONGOING)
Huntress has watched a ScreenConnect client flaw (**CVSS 9.9**) being exploited between **20 Oct and 16 Nov**. A "guest" in a support session can transfer and execute a payload on the connecting technician's host. In the observed chain, a batch file (`update_224ac089.bat`) reports to a Telegram bot, pulls a fake `WindowsUpdate.msi` and installs a rogue ScreenConnect client that connects to the attacker's relay, all in about 9 seconds. One MSP technician workstation was compromised on **12 Nov**. Attackers sent **688,000+** "run file" requests for `update*.bat` to 42 servers from 29 IPs. Huntress also counted **2,408** unauthorized guest sessions with crypto-exchange names on at least 118 self-hosted servers. No actor has been named. The playbook (abusing the MSP channel to reach many clients) mirrors the 2024 ScreenConnect mass exploitation. **Action:** Update technician host clients to **26.6.5 or later**. Until then, remove the **TransferFiles** permission from roles and session groups. Hunt for `update*.bat`, `Sync.bat` in Startup folders, `WindowsUpdate.msi`, `marker.txt`, the domain `masterdarky[.]com` and the IPs `91.224.92[.]167` and `74.208.158[.]106`. Isolate affected technician PCs and rotate every credential reachable from them.
Sources: [The Hacker News](https://thehackernews.com/2026/11/hackers-exploit-critical-screenconnect.html), [ConnectWise bulletin](https://www.connectwise.com/company/trust/security-bulletins/2026-09-08-screenconnect-bulletin)

### 1.2 Idunno.AntiCsrf CVE-2026-131914: unauthenticated RCE in an abandoned ASP.NET module, exploited, no patch
Mandiant/Google Cloud report in-the-wild exploitation of **CVE-2026-131914** (**CVSS 9.3**) in Idunno.AntiCsrf **0.9.1.0 / 0.9.1 Beta**. This is a WebForms double-submit-cookie CSRF module that has not been updated since 2008. The module deserializes the CSRF form token with an unkeyed `ObjectStateFormatter` and no MAC check. A single POST that carries any non-empty CSRF cookie plus a Base64 gadget chain gives code execution in `w3wp.exe`. This is the classic ViewState-deserialization playbook. The library is likely buried in legacy intranet and line-of-business apps. Google has not shared campaign details. **Action:** Search `Web.config` files and `bin/` folders for `Idunno.AntiCsrf` / `AntiCsrfModule`, and replace the module with `System.Web.Helpers.AntiForgery`, MAC-protected ViewState or ASP.NET Core `IAntiforgery`. Review IIS logs for unusual POSTs to `.aspx` pages that return 302/500 with large request bodies. If you suspect compromise, rotate `machineKey`, database and other secrets in `Web.config`/`applicationHost.config`, and sweep webroots for dropped files.
Sources: [The Hacker News](https://thehackernews.com/2026/11/hackers-exploit-critical-aspnet-anti.html), [TechJack Solutions](https://techjacksolutions.com/scc-intel/active-exploitation-of-abandoned-asp-net-anti-csrf-library-flaw-grants-unauthenticated-rce)

### 1.3 New KEV entries due 26 Nov: N-able MailAssure CVE-2026-134624 and MONAI Label CVE-2026-133968
On **23 Nov** CISA added two flaws to KEV, both with forensic triage required and a remediation deadline of **26 Nov**.
- **N-able MailAssure (SpamExperts) CVE-2026-134624** is an SSRF in the LDAP-sync connection check. An authenticated API user can reach internal hosts and ports and send crafted data to them. N-able tied the CVE to the intrusion into its Mail Assure/SpamExperts hosted cloud **(follow-up)**. The intrusion began **16 Nov** and was confined to one server, according to N-able. Portal/API access was restored **21 Nov**, and N-able promises a formal root-cause analysis within two weeks.
- **MONAI Label CVE-2026-133968** is a path traversal in the `PUT /datastore/image` and `/datastore/label` endpoints. It allows arbitrary file write and can lead to RCE. Authentication is **off by default**. Versions **≤0.8.5** are affected; the fix is **0.8.6**. The flaw is relevant to hospital and research AI imaging labs.

**Action:** MSPs and tenants of N-able's hosted Mail Assure should follow N-able's advisory, audit API users and LDAP-sync settings, rotate API credentials, and review outbound connections from filtering to internal hosts. MONAI users should upgrade to **0.8.6**, enable authentication, keep servers off untrusted networks, and look for files written outside the datastore (`authorized_keys`, cron entries).
Sources: [CISA KEV catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog), [N-able advisory](https://me.n-able.com/s/security-advisory/aArVy0000002mrlKAA), [The Hacker News (N-able)](https://thehackernews.com/2026/11/n-able-confirms-hackers-accessed-cloud.html), [MONAI GHSA-qc22-rmgc-vg94](https://github.com/Project-MONAI/MONAILabel/security/advisories/GHSA-qc22-rmgc-vg94)

### 1.4 Cisco Expressway CVE-2026-76466 and VMware vCenter CVE-2026-123890: perimeter-to-core intrusions, new IOCs (ONGOING)
F6 has published details of an intrusion via the hard-coded-credential / cluster-database flaw in **clustered** Expressway-C/E (fixed in **X15.5.20**). The attackers compromised two internet-facing Edge nodes and pivoted to internal cluster peers. From there, Python scripts scanned SMB shares, used SQL Server and WinRM, and searched GitLab for credentials. SecurityWeek also notes ongoing exploitation of SAP NetWeaver from the same KEV batch. Both KEV deadlines passed yesterday (23 Nov), together with vCenter **CVE-2026-123890**. For vCenter, Google says exploitation by the China-nexus cluster **ARMORY CASTLE** (BONESAW tooling) began in early September, so a patched vCenter may already be compromised. **Action:** Patch Expressway to **X15.5.20** or restrict TCP **4371–4372** to cluster peers. Hunt for `/mnt/harddisk/i????*/*.py`, the Erlang log entry `nodeup 'wombat@127.0.0.1'` and the IPs `66.179.31[.]32` and `18.130.47[.]116`. For vCenter, confirm 9.1.1.0200 / 9.0.2.0200 / 8.0 U3m, then hunt for persistence and rotate SSO/STS credentials.
Sources: [Help Net Security](https://www.helpnetsecurity.com/2026/11/23/cisco-expressway-vulnerability-exploited-cve-2026-76466/), [SecurityWeek](https://www.securityweek.com/sap-netweaver-cisco-expressway-flaws-exploited-in-attacks/), [BleepingComputer](https://www.bleepingcomputer.com/news/security/cisa-flags-critical-cisco-expressway-rce-flaw-as-actively-exploited/), [Rapid7 (vCenter, updated 23 Nov)](https://www.rapid7.com/blog/post/etr-cve-2026-123890-critical-authentication-bypass-vmware-vcenter/)

### 1.5 "GT13" campaign used Check Point Security Management Servers to reach 22–24 organisations
GreyNoise describes an unattributed operator, tracked as **GT13**, active from **2 Oct to 2 Nov** and probably still holding access. GT13 first compromised a Rejetto HFS server (**CVE-2026-61500**, session-cookie forgery) to use as a relay. It then abused the SmartConsole authentication bypass **CVE-2026-16232** (KEV since July; R81.10–R82.10) to run scripts on Check Point management servers and exfiltrate data from at least **22–24** victims. Other flaws were also tried, including Citrix CVE-2025-5777, Ivanti CVE-2024-21893 and NetLogon. GreyNoise suspects heavily automated, possibly AI-driven tooling but makes no attribution. **Action:** Confirm the July jumbo hotfix on all SMS/MDS servers. Audit `/root/.ssh/authorized_keys`, `/root/exfil/`, `/etc/ld.so.preload` (look for `/usr/lib/.libproc.so`) and any unexpected `pivot.p12` certificate. Block `newpayapp[.]com` and its subdomains, and check management-plane logs for the user-agent "Mozilla/5.0 research". If you find a hit, rotate the internal CA and admin credentials.
Sources: [GreyNoise](https://www.greynoise.io/blog/check-point-security-management-servers-intrusion-campaign), [Check Point advisory CPAI-2026-9895](https://advisories.checkpoint.com/defense/advisories/public/2026/cpai-2026-9895.html), [Rapid7 analysis](https://rapid7.com/blog/post/ra-check-point-smartconsole-authentication-bypass-technical-analysis-cve-2026-16232)
