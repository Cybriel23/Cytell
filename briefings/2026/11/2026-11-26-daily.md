## 1. Risk Watch

### 1.1 CISA KEV, 25 Nov: Xen Orchestra, Mitel MiCollab and Juniper Session Smart exploited, deadline 28 Nov (ONGOING)
CISA added 10 exploited CVEs, with most due **28 Nov**. The three most urgent:
- **Vates Xen Orchestra CVE-2026-133469 (VSA-2026-062, Critical).** A REST cookie of `authenticationToken=j:%7B%7D` is parsed as an empty object, and the token lookup then returns the first valid token, so an attacker gets Admin access. From there they can run code on managed pools and take root on XCP-ng hosts. Vates says a specific threat actor is exploiting it. Fixed in **XO 6.9.2 / 6.10.1** (xo-server **5.211.2** stable, **5.213.1** latest), and source installs should update to latest `master`.
- **Mitel MiCollab MISA-2026-0012.** Five AWV-component flaws in **10.3.0.18 and earlier**: blind command injection **CVE-2026-133323 (CVSS 10.0)**, XML injection **CVE-2026-133303 (9.0)**, auth bypass **CVE-2026-133324**, file upload **CVE-2026-133275** and weak authentication **CVE-2026-133311**. Four of them need no authentication. Mitel's advisory does not mention exploitation, but KEV listing confirms it. The fix is the patch in KB000129195, or a later release.
- **HPE Juniper Session Smart Conductor/Router CVE-2026-103406 (CVSS 9.8).** A crafted salt minion ID causes root command injection in the Conductor's AutomatedProvisioner. It was patched 28 Oct (JSA112183) in **7.0.5 / 7.1.7 / 7.2.3**, and Juniper SIRT has since received a report of exploitation. There are no workarounds.

MiCollab has a history of exploitation by ransomware and espionage actors (2024 path traversal chains). Xen Orchestra and SSR Conductors are management planes, so a compromise reaches every hypervisor or WAN edge they control.
**Action:** Patch all three before the weekend and take XO, MiCollab AWV and SSR Conductor management interfaces off the internet. For XO, look for a VM named `pivot2`, VMs using `hvm_serial: file`, `/etc/cron.d/zz-ustar*`, `/.ustar*` and `/etc/ld.so.preload` on XCP-ng hosts. If anything is found, rotate the pool secret, root password and backup-remote credentials, and reinstall. Vates warns that cleanup alone may miss backdoors.
**Sources:** [CISA KEV catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) · [Vates VSA-2026-062](https://docs.vates.tech/security-advisories/advisories/2026/vates-sa-2026-062) · [Mitel MISA-2026-0012](https://www.mitel.com/support/security-advisories/mitel-product-security-advisory-misa-2026-0012) · [TechRadar: Juniper SSR](https://www.techradar.com/pro/security/juniper-session-smart-routers-have-a-critical-flaw-so-patch-now)

### 1.2 GeoServer: exploitation attempts on the file-read to admin-forgery to RCE chain (NEW)
GeoServer published advisories on 24 Nov for flaws patched in October and November, and **watchTowr** reported in-the-wild attempts on 25 Nov. The flaws are:
- **CVE-2026-120705 (CVSS 8.6):** unauthenticated WFS file read and SSRF.
- **CVE-2026-129243 (8.8):** an OWS security-rule bypass using a prefixed service name such as `x/WFS`.
- **CVE-2026-129245 (9.2):** a hard-coded "remember me" signing key.
- **CVE-2026-129242 / -120704:** admin-to-code-execution through JDBC user services and HSQLDB deserialization.

The published chain reads `users.xml` and `security/config.xml`, forges an admin cookie, then gets code execution through JDBC. So far watchTowr sees probing: stored queries are created, checked and deleted. Full compromise is not confirmed, but GeoServer bugs have been weaponised fast before (CVE-2024-36401 was used against a US federal agency).
**Action:** Upgrade to **2.27.7 / 2.28.6 / 3.0.2**. If an instance was exposed, treat its password digests and signing key as compromised. Rotating the key does not help if the same file-read already leaked it. Hunt for stored-query create/delete bursts and unexpected JDBC user/role service configs.
**Sources:** [The Hacker News](https://thehackernews.com/2026/11/hackers-exploit-two-geoserver-flaws-as.html)

### 1.3 PAN-OS: Fragnesia kernel root bug CVE-2026-46300 now fixed (PAN-SA-2026-0015)
Palo Alto released PAN-OS fixes for **Fragnesia**, a Linux kernel XFRM ESP-in-TCP privilege escalation first disclosed in May. Fixes cover the 10.2, 11.1, 11.2, 12.1 and 12.2 branches, for example **12.2.4-h3** and **11.2.16-h3**. A Chinese-speaking actor used it after PHP2Shell (**CVE-2026-109618**) RCE on internet-exposed management interfaces to plant root-level webshells. In that AI-assisted campaign, **24 firewalls and a management server** were compromised in October. Palo Alto says PHP2Shell-fixed builds already block the known initial-access path but still recommends the kernel fix.
**Action:** Apply both the PHP2Shell and the Fragnesia fixes. Make sure the management interface is reachable only from a management network or VPN. If the interface was ever internet-exposed during October, hunt for webshells and root persistence.
**Sources:** [Palo Alto PAN-SA-2026-0015](https://security.paloaltonetworks.com/PAN-SA-2026-0015) · [SecurityWeek](https://www.securityweek.com/palo-alto-networks-patches-fragnesia-flaw-used-to-root-firewalls/)

### 1.4 Developer-platform breaches: 1Password, Todoist, Hex.pm (ROTATE / PHISHING ALERT)
- **1Password:** An attacker used an employee's corporate **GitHub account** to reach private repos and inject code into backend services. The code pulled customer account records: names, emails, account IDs, public keys, **SRP parameters**, and **invitation, provisioning and recovery tokens**. The attacker also reached CI/CD. Detection was on **19 Nov** and disclosure on 25 Nov. Vaults and their keys were not affected. The stolen tokens need SSO or an emailed code to use, and 1Password has made those codes longer (10 alphanumeric characters). A small number of users were notified.
- **Todoist:** Stolen credentials gave access to version control and then cloud infrastructure on **22–23 Nov**. About **6% of customers** had emails and password hashes taken, with legacy hashes for early users. Some users also lost API and Slack tokens and Outlook add-on data (emails and attachment names). For a tiny subset, the attacker searched their tasks for credentials.
- **Hex.pm (Elixir/Erlang registry):** A pre-auth deserialization RCE, **CVE-2026-129514 (CVSS 10.0)** and latent since 2016, was exploited on 23 Nov between 18:16 and 18:29 UTC. Six servers were compromised. No packages appear altered, but the account database (emails, password and API-key hashes, **2FA secrets**) may have been read.

**Action:** 1Password admins should expect targeted phishing about "recovery" or "invitations" and remind users not to share codes or Secret Keys. Todoist users should reset passwords, regenerate API tokens, reconnect integrations and revoke any secrets stored in tasks. Hex users should change their password, reset 2FA, re-auth with `mix hex.user auth`, fetch only from repo.hex.pm until the new client ships, and patch self-hosted registries. Across all three cases, review how engineer GitHub and SCM accounts are protected (phishing-resistant MFA, short-lived tokens).
**Sources:** [TechCrunch: 1Password](https://techcrunch.com/2026/11/25/1password-said-hackers-broke-into-its-internal-systems-but-customer-passwords-are-safe/) · [BleepingComputer: 1Password](https://www.bleepingcomputer.com/news/security/1password-customer-data-stolen-after-employee-github-account-breach/) · [TechCrunch: Todoist](https://techcrunch.com/2026/11/25/todoist-confirms-6-of-customers-details-were-stolen-in-data-breach/) · [The Hacker News: Hex.pm](https://thehackernews.com/2026/11/hackers-exploited-cvss-100-hexpm-rce.html)

## 4. Threat Watch
- **ARTEX agentic attack framework in state hands:** Microsoft Threat Intelligence names **Salt Typhoon, Crystal Typhoon, Onyx Sleet, Pearl Sleet, Storm-0940 and Storm-3358** as users of ARTEX. It is an open-source, LLM-orchestrated pentest platform released in July and now also sold as "ARTEX Pro". Observed activity includes Storm-0940 supply-chain intrusions on IT vendors (an app that assigned itself Global Administrator, 151k failed sign-ins peaking at 2,900/min, privileged access in under 3 hours) and a move from leaked client secrets to Key Vault in 5 minutes. Network IOCs rotate. Hunt for the user agents `artex-enrich/*` and `norma/*`, machine-speed request bursts and Defender detection `Behavior:Win64/ArtexAI`. [Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2026/11/25/what-defenders-need-to-know-artex-agentic-ai-framework-threat-actors-abuse/) · [The Record](https://therecord.media/microsoft-china-salt-typhoon-using-artex-ai-tool)
- **Com-affiliated vishing clusters (Unit 42):** Seven clusters have run vishing and AiTM against SSO since August: **Bling Libra/ShinyHunters**, CL-CRI-1116 (Redact), 1147 (Pink), 1182 (Falcon), 1192 (Helix/UNC6671), 1264 (Vortex) and 1274 (Cinder). Targets are in the US, UK and Australia, and healthcare overtook finance in September. Tradecraft: Doko's Panel kit, quick MFA-device enrolment (a reused "Pixel 10a" device name), rogue OAuth apps, Graph SDK exfiltration from M365, and a sideloaded "Google Chrome" extension with CDP-based C2. [The Hacker News](https://thehackernews.com/2026/11/com-affiliated-hackers-hijack-cloud.html)
