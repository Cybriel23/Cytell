# Daily Cyber Threat Intelligence Briefing
Friday, 27 November 2026 · Coverage: 26 Nov 2026 06:00 UTC – 27 Nov 2026 06:00 UTC and follow-ups on tracked topics

## Executive Summary
The US Thanksgiving holiday slowed the news flow, and CISA added nothing to KEV on 26 Nov. Several live issues still need attention before the weekend. First, Drupal disclosed a second installer flaw, **CVE-2026-136716 (SA-CORE-2026-019)**, which is exploited for site takeover. It catches sites that the 18 Nov Fail2Install patch left in an incomplete install state, and fixing it requires both upgrading and running `update.php`. Second, the North Korea-linked **PolinRider** worm has altered at least **7,600 GitHub repositories**. It rewrites commits with stolen developer credentials and has force-pushed malicious changes into pull requests at AsyncAPI, CircuitVerse and Open Food Facts, which puts every org that builds from GitHub at risk. Third, Accenture reports that the **Mitel MiCollab** zero-days were exploited **before** Mitel's 16 Nov advisory, with root in 30 minutes and Active Directory reached within a day. The KEV deadline for MiCollab, **Xen Orchestra** and **Juniper SSR** falls on **28 Nov** (Saturday). Fourth, the official **SoftwareOK** download site served trojanized **Q-Dir** and **DesktopOK** installers that drop a Python RAT. Watch this week for: the expiry of The Gentlemen's NVIDIA countdown (~28 Nov), Inception's claimed McDonald's deadline (27 Nov), further Drupal mass-exploitation telemetry, HPE's bulletin for the reported AirWave auth bypass, and early-December Android and Chrome security releases.

## 1. Risk Watch

### 1.1 Drupal core CVE-2026-136716 (SA-CORE-2026-019): second installer takeover flaw, exploited in the wild (ONGOING)
Drupal rates the access bypass in `install.php` **Highly critical (21/25)**. It needs no authentication, and Drupal says it "is being exploited in the wild." SA-CORE-2026-017 (Fail2Install, **CVE-2026-132165**, KEV due **today, 27 Nov**) did not protect sites left in an unusual or incomplete install state, and Drupal says you cannot tell from the UI whether a site is in that state. Affected: Drupal **10 < 10.6.23**, **11.0–11.3.22** and **11.4.0–11.4.13**. Fixed: **10.6.23 / 11.3.23 / 11.4.14**. Branches 10.5.x and 11.2.x and older are end-of-life and get no fix. Secondary reporting puts exposure in the tens of thousands of sites, and there are reports of hijacked government sites.
**Action:** Upgrade, **then run `update.php`**, which Drupal says is required to fix sites already in the affected state. Block or remove remote access to `install.php`. Check logs for changes to or by **user 1** and reset that account's email and password. Treat any site whose installer was reachable after 18 Nov as possibly compromised and follow Drupal's "site got hacked" guidance. Drupal Steward mitigations block the known vectors but are not a substitute for upgrading.
**Sources:** [Drupal SA-CORE-2026-019](https://www.drupal.org/sa-core-2026-019) · [The Hacker News](https://thehackernews.com/2026/11/drupal-warns-of-new-highly-critical.html) · [SecurityWeek](https://www.securityweek.com/drupal-installer-patch-left-a-gap-attackers-are-already-exploiting/)

### 1.2 PolinRider (DPRK): commit-rewriting worm poisons 7,600+ GitHub repos and open-source pull requests (ONGOING)
Apiiro counts at least **7,609 repositories across 2,330 accounts**, and **2,040** of those were pushed between 27 Oct and 6 Nov. SafeDep found the loader in 375 public repos. The worm uses stolen GitHub credentials to rewrite developers' existing commits. It keeps the original author, message and date, hides a roughly 58-line Python loader (in `conftest.py`, a small utils package, or after hundreds of spaces in a build config), and force-pushes. The account **Eternity0207** opened more than 200 PRs. Payloads stayed on branches for 30–40 minutes. **AsyncAPI Generator, CircuitVerse and Open Food Facts** were hit, and CircuitVerse CI reportedly published 40 infected installers. The loader triggers on `npm run build`, on loading a test config, or on opening the folder in VS Code. It reads its C2 from Ethereum wallet transactions ("NullReceiver", using EtherHiding), so taking down servers does not stop it. Second-stage payloads tamper with VS Code, Cursor and GitHub Desktop and steal secrets and wallets. Researchers assess PolinRider as a sub-cluster of Contagious Interview, which also uses fake take-home assessments (BlockNovas, AccuraSoftHire, HuntRole).
**Action:** Audit repos for unexpected force-pushes and commits whose dates don't match their pushes. Grep for `conftest.py` or utils files that make Ethereum RPC calls or spawn `node -i`, and for long whitespace runs in build configs. Rotate GitHub PATs and OAuth tokens on developer machines and enforce branch protection that blocks force-pushes. Block **accurasofthire[.]com**, **huntrole[.]org**, **103.179.142[.]155**, **95.135.181[.]84** and **95.135.181[.]151**. Remove the `huntrole.assessment-tool` VS Code extension and hunt for `fa-solid-400.woff2` / `fa-solid-500.woff2` payload carriers.
**Sources:** [The Hacker News](https://thehackernews.com/2026/11/north-korea-linked-polinrider-poisons.html) · [GBHackers](https://gbhackers.com/github-pull-requests/) · [StepSecurity](https://stepsecurity.io/blog)

### 1.3 Mitel MiCollab: zero-days exploited before the advisory, suspected AI-assisted extortion; KEV deadline 28 Nov (follow-up)
Accenture Apex Labs reports that attackers deployed a web shell on a victim's MiCollab server on **15 Nov**, a day before Mitel's advisory, and that a second server had been talking to attacker infrastructure since **9 Nov**. On the first victim, commands ran 12 minutes after the first request, the attackers had root within about 30 minutes, and in about 20 hours they reached backup and database servers and AD-integrated identity infrastructure and stole business data. The attacker infrastructure talked to two commercial AI APIs, and that traffic resumed at the exact second the auth-bypass request was sent. Accenture suspects extortion. The five AWV flaws are **CVE-2026-133323 (CVSS 10.0)**, -133303, -133324, -133275 and -133311 in **10.3.0.18 and earlier**. Mitel's advisory still does not mention exploitation. The same KEV batch (due **28 Nov**) includes **Xen Orchestra CVE-2026-133469** and **Juniper Session Smart CVE-2026-103406**.
**Action:** Patch MiCollab (KB000129195 or later) and take AWV off the internet. Because exploitation predates the patch, **hunt even on patched servers**: look for web shells in the AWV web root, unexpected root processes, and outbound connections to AI API endpoints from the server. Review AD for credential use originating from MiCollab hosts. Finish Xen Orchestra and SSR patching this weekend.
**Sources:** [SecurityWeek](https://www.securityweek.com/mitel-micollab-zero-days-exploited-in-suspected-ai-assisted-attacks/) · [CISA KEV catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)

### 1.4 SoftwareOK supply-chain compromise: trojanized Q-Dir and DesktopOK installers drop a Python RAT (NEW)
AhnLab ASEC found that some installers downloaded from the **official SoftwareOK site** did not match the SHA-256 values on the download page. Named versions: **Q-Dir 12.83/12.84/12.85** and **DesktopOK 12.82/12.85**. The built-in updaters also fetched the malicious builds. Each installer runs a legitimate, signed copy of the tool so nothing looks wrong. It also downloads `7zr.exe` and `dsv2_py39_agent.7z` from **mail.c1a2[.]top**, unpacks a bundled Python runtime to `C:\ProgramData\Microsoft\DeviceSync\b2` (or `C:\ProgramData\DeviceSync\b2`), and persists through the scheduled task `\UPnp\MicrosoftEdge_dcntel`. The RAT runs shell and Python commands, moves files, takes screenshots, and checks running processes against 1,206 security-product names. C2 is **8.210.69[.]51:9876**. It contains Chinese-language strings, but there is no attribution.
**Action:** Inventory Q-Dir and DesktopOK, which are popular with admins and power users. Hunt for the task name, the `DeviceSync\b2` folder, `pythonw.exe` running from ProgramData, and traffic to the C2 above. Uninstalling the tool does **not** remove the RAT, so isolate and rebuild any hits. Get hashes from the ASEC report.
**Sources:** [AhnLab ASEC](https://asec.ahnlab.com/ko/96826/)
