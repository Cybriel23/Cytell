## Executive Summary
News volume was moderate as the US holiday ended, but the operational risk is high. Four things matter most today. First, two exploited bugs are spreading fast: Drupal's **Fail2Install** follow-up (**CVE-2026-136716**) and a **GeoServer** unauthenticated chain. CISA added both to KEV on 27 November with a **30 November** deadline. An **unpatched Cacti 1.2.31** RCE with a public PoC also needs an immediate mitigation: disable guest access. Second, KEV deadlines for **Juniper Session Smart Conductor (CVE-2026-103406)** and four **Mitel MiCollab** flaws fall **today, 28 November**. Third, a developer-identity pattern is emerging. **SAP** confirmed an intrusion into its GitHub development infrastructure, reportedly through stolen employee tokens, two days after **1Password** disclosed a breach that also started with an employee's GitHub account. Fourth, government incidents are unresolved at the **US Air Force (Cloud One)** and the **UK DWP**, and national CERTs in Switzerland, Italy and the UK now confirm intrusions run by AI agents. Watch this week for: a Cacti fix and CVE for 4HTTP2SHELL, SAP's findings on code integrity and signing keys, Air Force/DoD confirmation of the Cloud One scope, DWP service restoration and any claim of responsibility, Tomcat **11.0.30/10.1.63/9.0.125** shipping the fix for **CVE-2026-133325**, and early-December KEV additions (Mitel CVE-2026-133311 and Danfoss CVE-2025-41450 are due 9 December).

## 1. Risk Watch

### 1.1 Drupal "Fail2Install" installer takeover: CVE-2026-132165 and CVE-2026-136716 (ONGOING, KEV due 30 Nov)
Drupal says **SA-CORE-2026-017** (**CVE-2026-132165**, CVSS **9.8**, unauthenticated reinstall that leads to an admin account and sometimes RCE) has been exploited on live sites since **2026-11-19 19:00 UTC**. The follow-up **SA-CORE-2026-019** (**CVE-2026-136716**) covers sites stuck in incomplete or unusual install states that the first patch missed, and it is also being exploited. CISA added CVE-2026-136716 to KEV on 27 November (due **30 Nov**). CVE-2026-132165's deadline passed on 27 November. Roughly **31,500 of ~55,800** internet-facing Drupal sites ran vulnerable branches. Drupal warns that attacker admin accounts and backdoors **survive upgrades**, and no new core advisory has appeared since 25 November.
**Action:** Upgrade to **10.6.23 / 11.3.23 / 11.4.14** and run the database updates. Block `/core/install.php` at the edge. Any site whose installer was reachable since 18 November should be treated as possibly compromised: review user 1 activity and its email and password, look for unexpected admin accounts, modules and PHP files, and isolate end-of-life branches, which get no fix.
**Sources:** [Drupal SA-CORE-2026-019](https://www.drupal.org/sa-core-2026-019) · [Drupal SA-CORE-2026-017](https://www.drupal.org/sa-core-2026-017) · [CISA KEV alert 27 Nov](https://www.cisa.gov/news-events/alerts/2026/11/27/cisa-adds-three-known-exploited-vulnerabilities-catalog) · [Malwarebytes](https://www.malwarebytes.com/blog/bugs/2026/11/drupal-sites-are-being-hijacked-and-a-follow-up-flaw-is-already-under-attack) · [CSA CISO briefing](https://labs.cloudsecurityalliance.org/research/alt-ciso-briefing-2026-11-27/)

### 1.2 GeoServer unauthenticated chain: CVE-2026-120705 and CVE-2026-129243 now exploited (NEW KEV, due 30 Nov)
CISA added two GeoServer flaws to KEV on 27 November. **CVE-2026-120705** is an unauthenticated XML injection in WFS 2.0 `GetFeatureById` that reads local files or forces SSRF. **CVE-2026-129243** bypasses service-level security rules with a prefixed service name such as `x/WFS`. GeoServer's own write-up shows both are steps in a five-CVE chain to **administrator-level code execution**. The chain runs through data-directory path disclosure (**CVE-2026-129244**), a predictable remember-me key that allows admin session forgery (**CVE-2026-129245**, Critical), and JDBC user/role service deserialization (**CVE-2026-129242**). Fixes shipped in **3.0.2 / 2.28.6 / 2.27.7** (19 October). GeoServer has been a repeat target in 2026, including an August SQLi zero-day.
**Action:** Upgrade to 3.0.2, 2.28.6 or 2.27.7. Until then, restrict WFS/OWS endpoints to trusted networks. Hunt web logs for `GetFeatureById` stored-query requests with unusual `ID` values and for `service=` parameters with path prefixes. Rotate the remember-me key and admin credentials on any instance that was exposed.
**Sources:** [GeoServer security update](https://geoserver.org/vulnerability/2026/11/23/cve-update.html) · [GHSA-39mw-5chv-jh47](https://github.com/geoserver/geoserver/security/advisories/GHSA-39mw-5chv-jh47) · [GHSA-rv5g-g2r9-58rj](https://github.com/geoserver/geoserver/security/advisories/GHSA-rv5g-g2r9-58rj) · [CISA KEV alert 27 Nov](https://www.cisa.gov/news-events/alerts/2026/11/27/cisa-adds-three-known-exploited-vulnerabilities-catalog)

### 1.3 KEV deadlines today: Juniper Session Smart Conductor CVE-2026-103406 and Mitel MiCollab (ONGOING)
Juniper updated its advisory to flag **CVE-2026-103406** (CVSS **9.8**) as exploited, with at least one malicious case reported to its SIRT. The bug is an OS command injection in the Session Smart Conductor **AutomatedProvisioner** service. A crafted Salt minion ID gives root command execution. Fixed in **7.2.3 / 7.1.7 / 7.0.5** (patched 28 October with 17 other SSR/Conductor fixes). Mitel MiCollab **CVE-2026-133324, -133275, -133303, -133323** also reach their KEV deadline today. **CVE-2026-133311** is due 9 December. These were exploited before an advisory existed, in AI-assisted extortion activity covered earlier this week. CISA has not tied any of them to a named actor.
**Action:** Patch Conductor and SSR now. Review Conductor logs for unexpected router registrations and odd minion IDs, and check for new root-level processes or cron entries. On MiCollab, apply Mitel's current release, restrict the management interfaces, and hunt for web shells and unexpected accounts.
**Sources:** [SecurityWeek (Juniper)](https://www.securityweek.com/critical-juniper-session-smart-conductor-flaw-exploited-in-attacks/) · [CISA KEV catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) · [IT-Connect KEV roundup](https://www.it-connect.fr/danfoss-mitel-juniper-xen-orchestra-10-failles-exploitees-cisa/)

### 1.4 Developer-identity compromises at SAP and 1Password: GitHub tokens as the entry point (DEVELOPING)
On 27 November **SAP** confirmed it is investigating a cybersecurity incident in its development infrastructure. It says it has "no evidence of unauthorized access to customer business data." The rest comes from press reporting (Der Spiegel, Handelsblatt) and is **not confirmed by SAP**: attackers reportedly used stolen employee authentication tokens to **copy and alter source code on GitHub**, possibly with AI assistance, and SAP replaced **signing keys**, restricted GitHub access and paused automated development pipelines. No reporting so far says tampered code reached customers. SecurityWeek says this does not appear linked to The Gentlemen's October leak-site listing of SAP. Separately (follow-up), **1Password** says an employee's corporate GitHub account was compromised from **19 November**. The attacker pushed malicious code to backend services and took private source code, CI/CD access, customer records (names, emails, public keys, SRP verifiers, metadata) and provisioning/recovery email tokens. 1Password says vaults and vault keys were not accessed.
**Action:** Rotate GitHub PATs, OAuth apps, deploy keys and Actions secrets used by staff with production or signing access, and enforce SSO, short-lived tokens and fine-grained PATs. Review GitHub audit logs for new tokens, workflow edits and pushes to protected branches. For SAP estates, watch for SAP security notes on signing-key rotation and validate signatures on recently downloaded SAP tools and SDKs. 1Password customers should expect targeted phishing.
**Sources:** [SecurityWeek (SAP)](https://www.securityweek.com/sap-confirms-cyberattack-source-code-reportedly-compromised/) · [Techzine](https://www.techzine.eu/news/security/146116/sap-hit-by-hack-source-code-modified/) · [SecurityWeek (1Password)](https://www.securityweek.com/1password-breach-exposes-customer-data-internal-source-code/)

### 1.5 Cacti "4HTTP2SHELL/4HTTP2ROOT" zero-day: unauthenticated RCE through guest access (UNPATCHED, public PoC)
A researcher disclosed a four-request chain against **Cacti 1.2.31**, the latest release, on 26 November and published a **public PoC** on GitHub. Previdian confirmed it. No CVE or fix exists yet. The precondition is that the **guest account is enabled**; it has been off by default since 0.8.7. The chain:
1. The guest writes a string into the numeric `preview_graphs_per_page` setting via `auth_profile.php?action=update_data`.
2. Loading `graph_view.php` turns that stored value into a second-order **stacked-query SQL injection** that rewrites the poller table.
3. `graph_realtime.php` passes the modified poller row to PHP `popen()`, which gives code execution as the Cacti user.

Cacti often stores network-device credentials, so a compromise opens the way for lateral movement and alert suppression. No in-the-wild exploitation is reported yet, but a public PoC for a monitoring tool usually draws scanning within days.
**Action:** Disable the guest account now (Console → Configuration → Settings → Authentication → Guest User = none). Restrict the Cacti UI to admin networks. Review poller and data-input entries for unexpected command strings. Hunt web logs for guest-session requests to `auth_profile.php?action=update_data` followed by `graph_realtime.php`. Rotate stored SNMP and device credentials if anything looks off.
**Sources:** [The Hacker News](https://thehackernews.com/2026/11/unpatched-cacti-zero-day-enables-rce-in.html) · [GBHackers](https://gbhackers.com/cacti-4http2root-zero-day/)
